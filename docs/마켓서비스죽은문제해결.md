## 1. Trading Engine Stale Data 문제

### 증상
- Slack 알림: "market-data-service 상태 확인 필요"
- trading-engine 로그에 `strategy_stopped`, `stale_data` 반복 출력
- 포지션이 있지만 전략이 실행되지 않음

### 로그 예시
```json
{"event": "stale_data_alert", "stale_market_count": 0, "max_delay_sec": 0}
{"event": "strategy_stopped", "reason": "stale_data"}
```

### 원인
1. 일시적인 네트워크 문제나 데이터 지연으로 모든 마켓이 stale 처리됨
2. `self._markets` 리스트가 비게 됨
3. 이후 복구되어도 마켓 리스트가 비어있어 계속 실패

### 진단 방법

```bash
# 1. kubectl context 확인 (EKS vs 로컬 k3s)
kubectl config current-context

# EKS로 전환
kubectl config use-context <user>@<cluster-name>.<region>.eksctl.io

# 2. trading-engine 로그 확인
kubectl -n coinbot logs deployment/trading-engine --tail=50

# 3. stale 발생 시점 확인
kubectl -n coinbot logs deployment/trading-engine | grep "stale_markets_excluded" | tail -10

# 4. market-data-service 정상 동작 확인
kubectl -n coinbot logs deployment/market-data-service --tail=20
```

### 해결 방법

#### 방법 1: 파드 재시작 (권장)
```bash
# 현재 파드 삭제 (ReplicaSet이 새 파드 생성)
kubectl -n coinbot delete pod -l app=trading-engine

# 또는 rollout restart
kubectl -n coinbot rollout restart deployment trading-engine
```

#### 방법 2: 이미지 pull 실패 시
```bash
# 동작 중인 파드의 이미지 확인
kubectl -n coinbot get pod <running-pod-name> -o jsonpath='{.spec.containers[0].image}'

# 해당 이미지로 deployment 업데이트
kubectl -n coinbot set image deployment/trading-engine trading-engine=<working-image>
```

### 예방 조치
- market-data-service 모니터링 강화
- stale 마켓 복구 로직 개선 고려 (매 iteration마다 마켓 리스트 재초기화)

## 2. ImagePullBackOff 문제

### 증상
```
NAME                              READY   STATUS             RESTARTS   AGE
trading-engine-xxxxx              0/1     ImagePullBackOff   0          1h
```

### 원인
1. `ghcr-secret` 삭제됨 (GHCR 이미지 사용 시)
2. ECR 인증 만료
3. 이미지 태그가 존재하지 않음

### 진단 방법

```bash
# 1. 이벤트 확인
kubectl -n coinbot describe pod <pod-name> | grep -A5 "Events:"

# 2. 시크릿 확인
kubectl -n coinbot get secret ghcr-secret
kubectl -n coinbot get secret ecr-secret

# 3. 현재 사용 중인 이미지 확인
kubectl -n coinbot get deployment trading-engine -o jsonpath='{.spec.template.spec.containers[0].image}'
```

### 해결 방법

#### GHCR Secret 재생성
```bash
kubectl -n coinbot create secret docker-registry ghcr-secret \
  --docker-server=ghcr.io \
  --docker-username=<github-username> \
  --docker-password=<github-pat> \
  --docker-email=<email>
```

#### ECR 이미지 사용 (권장)
```bash
# 동작 중인 파드의 ECR 이미지로 전환
WORKING_IMAGE=$(kubectl -n coinbot get pod <running-pod> -o jsonpath='{.spec.containers[0].image}')
kubectl -n coinbot set image deployment/trading-engine trading-engine=$WORKING_IMAGE
```

#### 실패한 ReplicaSet 정리
```bash
# 실패하는 RS 확인
kubectl -n coinbot get rs -l app=trading-engine

# 실패하는 RS 스케일 다운 (Deployment가 다시 올릴 수 있음)
kubectl -n coinbot scale rs <failed-rs-name> --replicas=0
```

## 3. 일반적인 디버깅 명령어

### Kubectl Context 관리
```bash
# 현재 context 확인
kubectl config current-context

# 모든 context 목록
kubectl config get-contexts

# EKS로 전환
kubectl config use-context <user>@<cluster-name>.<region>.eksctl.io

# 로컬 k3s로 전환
kubectl config use-context default
```

### 파드 상태 확인
```bash
# 모든 파드 상태
kubectl -n coinbot get pods

# 특정 앱 파드만
kubectl -n coinbot get pods -l app=trading-engine

# 파드 상세 정보
kubectl -n coinbot describe pod <pod-name>
```

### 로그 확인
```bash
# 최근 로그
kubectl -n coinbot logs deployment/trading-engine --tail=100

# 실시간 로그
kubectl -n coinbot logs -f deployment/trading-engine

# 특정 키워드 필터링
kubectl -n coinbot logs deployment/trading-engine | grep -E "error|stale|failed"

# 이전 파드 로그 (재시작된 경우)
kubectl -n coinbot logs <pod-name> --previous
```

### 환경변수 확인
```bash
# ConfigMap 확인
kubectl -n coinbot get configmap coinbot-config -o yaml

# Secret 목록
kubectl -n coinbot get secrets

# 파드 내부 환경변수
kubectl -n coinbot exec <pod-name> -- env | grep -E "REAL_MODE|ALLOWED"
```

### Redis 확인
```bash
# Redis 파드에서 직접 확인
kubectl -n coinbot exec -it deployment/redis -- redis-cli

# 캔들 데이터 확인
> KEYS candles:*
> GET candles:KRW-BTC:1m
```

### Deployment 관리
```bash
# 롤아웃 상태
kubectl -n coinbot rollout status deployment/trading-engine

# 롤아웃 히스토리
kubectl -n coinbot rollout history deployment/trading-engine

# 이전 버전으로 롤백
kubectl -n coinbot rollout undo deployment/trading-engine

# 특정 리비전으로 롤백
kubectl -n coinbot rollout undo deployment/trading-engine --to-revision=<N>
```

## 트러블슈팅 체크리스트

문제 발생 시 순서대로 확인:

1. [ ] kubectl context가 올바른지 확인 (EKS vs 로컬)
2. [ ] 모든 파드 상태 확인 (`kubectl get pods`)
3. [ ] 문제 파드 이벤트 확인 (`kubectl describe pod`)
4. [ ] 로그에서 에러 확인 (`kubectl logs`)
5. [ ] ConfigMap/Secret 설정 확인
6. [ ] 필요시 파드 재시작 또는 롤백
